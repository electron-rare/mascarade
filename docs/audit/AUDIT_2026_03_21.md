## 2. Complexity Hotspot Analysis

### 2.1 router/router.py (1051 LOC) — P1 CRITICAL BUG + P2 refactor

**CRITICAL BUG: Triple `_select_provider` call (lines 654-656 and 925-927)**

Both `send()` and `stream()` contain this pattern:
```python
selected = self._select_provider(attempt_enum, attempt_provider, domain)
selected = self._select_provider(attempt_enum, attempt_provider, detected_domain)
selected = self._select_provider(attempt_enum, attempt_provider)
```
The first two calls are wasted — `selected` is immediately overwritten. The third call passes no domain at all, meaning **domain-aware routing is completely broken**. This appears to be an accidental merge artifact. The intended logic is likely a single call with the correct domain.

**BUG: stream() missing `await` on cache.retrieve (line 896)**

`self.cache.retrieve(...)` is an async method but is called without `await` in the `stream()` method. The result is always a coroutine object (truthy), so the cache comparison logic is broken — streaming always tries to yield a coroutine object as the cached response.

**BUG: cluster.py `forward_send` double HTTP call (lines 783 + 801)**

`forward_send()` fires an HTTP POST to `/v1/cluster/node/send` (line 783), discards its result, then tries P2P, then falls back to a second HTTP POST to `/cluster/node/send` (line 801) — two different paths. The first call's result (`remote`) is never used. This doubles latency and load on the remote peer.

**Duplication: `send()` and `stream()` share ~70% identical structure.**

Metrics tracking, cost logging, fallback iteration, circuit breaker checks, and RouteLLM resolution are copy-pasted between `send()` and `stream()`. This is the root cause of the triple-call bug appearing in both methods.

**Unused import: `track_usage`** (line 28) is imported but only referenced in commented-out TODO blocks.

**Unused attribute: `cost_calculator`** (line 117) is initialized but never used anywhere in the file.

**Recommended refactoring:**
1. **P1 — Fix triple `_select_provider`**: Replace the 3 calls with a single call using the best available domain (`domain or detected_domain or None`).
2. **P1 — Fix `await` on cache.retrieve in `stream()`**: Add `await`.
3. **P1 — Fix `forward_send` double HTTP call**: Remove the unused first HTTP call or restructure the fallback logic.
4. **P2 — Extract shared logic**: Create `_execute_with_fallback()` generator that handles the iteration/metrics/circuit-breaker pattern once.
5. **P3 — Remove unused imports/attributes**: `track_usage`, `cost_calculator`.

### 2.2 mcp/client.py (1451 LOC) — P2 refactor

**Issues:**

1. **Massive code duplication in subprocess lifecycle management.** The same pattern (spawn process, initialize JSON-RPC, send request, handle timeout, cleanup stdin/wait/kill) is repeated 4 times: `call_tool()`, `describe_server()`, `read_resource()`, and partially in `call_tool_http()`. Each copy has its own `_request()` inner function with identical error handling.

2. **Environment setup duplicated.** The `env = os.environ.copy(); env["MASCARADE_DIR"] = ...; env["KILL_LIFE_ROOT"] = ...` block appears 3 times verbatim (lines 434-444, 849-853, 958-962).

3. **Convenience wrappers add pure boilerplate (lines 1042-1451).** The bottom ~400 lines are thin wrappers (`knowledge_base_search`, `freecad_create_document`, `graphiti_search`, etc.) that only forward parameters to `call_tool()`. They add no validation or transformation beyond what `call_tool()` already does.

4. **No connection reuse.** Each `call_tool()` invocation spawns a new subprocess, runs the full MCP handshake (initialize + initialized notification), then tears down. For high-frequency tool calls this is expensive.

**Security — OK.** FreeCAD script validation (`_validate_freecad_script`) uses AST-based sandboxing with allowlists. The `call_tool()` method does not interpolate user input into shell commands — it uses `asyncio.create_subprocess_exec` with a fixed command tuple. No command injection risk found.

**Recommended refactoring:**
1. **P2 — Extract `_run_stdio_session()` context manager** that handles subprocess spawn, environment setup, JSON-RPC initialize handshake, and cleanup. `call_tool()`, `describe_server()`, and `read_resource()` become 10-line methods.
2. **P3 — Consider making convenience wrappers optional** (move to a separate `mcp/convenience.py` or keep them but acknowledge they are pure API sugar).

### 2.3 node_engine/workers/electronics/component_nodes.py (1573 LOC) — P3 refactor

**Issues:**

1. **Entirely mock implementation.** Every node class returns hardcoded mock data. None of the nodes actually query LCSC, JLCPCB, or any real database. The file is essentially a scaffold with zero production logic.

2. **Duplicate node: `BomGeneratorNode` vs `BomGenerateNode`.** Two classes do the same thing (generate BOM) with near-identical implementations:
   - `BomGeneratorNode` (line 483, type `electronics.component.bom_generator`)

5. **f-string logging.** Multiple `logger.info(f"...")` calls should use `logger.info("...", arg)` for lazy evaluation.

**Recommended refactoring:**

2. **P3 — Remove unused imports** (`asyncio`, `field`).
3. **P3 — Consider a declarative port definition** pattern to reduce per-node boilerplate.
4. **P3 — Mark file as "scaffold only"** until real API integrations are added.

### 2.4 cluster.py (1112 LOC) — P2 refactor

**Issues:**

1. **CRITICAL BUG: `forward_send` fires HTTP then tries P2P** (see section 2.1). The first HTTP call on line 783 is never consumed if P2P succeeds, and the fallback HTTP on line 801 hits a different path (`/cluster/node/send` vs `/v1/cluster/node/send`). This results in double-execution on the remote peer.

2. **`_p2p_local_send` creates a new event loop per call** (line 429). This is a known anti-pattern — `asyncio.new_event_loop()` is expensive and risks deadlocks if called from within an existing async context. The libp2p backend calls this from a trio thread, but it should use `asyncio.run_coroutine_threadsafe()` instead.

3. **`probe_peers` is sequential** (line 733-740). Each peer is probed one at a time with `await self._probe_peer(peer)`. For N peers this takes N * timeout worst case. Should use `asyncio.gather()`.

4. **`select_route` probes all peers before selecting** (lines 839-841). This means every routing decision pays the full probe latency. Consider caching probe results with a TTL.

5. **`_discover_mdns_peers_sync` uses `time.sleep(0.1)` in a busy loop** (line 670). This blocks the thread pool thread for the scan timeout duration. The sleep granularity (100ms) is unnecessarily fine.

**Recommended refactoring:**
1. **P1 — Fix `forward_send` double HTTP call**: Remove line 783 or restructure so HTTP is only the fallback.
2. **P2 — Parallelize `probe_peers`**: Use `asyncio.gather(*[self._probe_peer(p) for p in self._peers])`.
3. **P2 — Cache probe results**: Add a TTL-based cache to `select_route` to avoid probing on every request.
4. **P3 — Fix `_p2p_local_send`**: Use `asyncio.run_coroutine_threadsafe()` on the main loop.

## 3. Security Findings

### 3.1 Command Injection — LOW RISK

- **MCP client.py**: Uses `asyncio.create_subprocess_exec()` with a fixed command tuple. Server keys are looked up from a hardcoded registry — no user input flows into the command. **No injection vector found.**
- **finetune agents**: `subprocess.run()` calls in `student.py`, `analyst.py`, `reinforcer.py`, `validator.py` use list-based arguments (no shell=True). Model paths come from internal pipeline state, not from user HTTP input. **Low risk but no input validation on paths.**
- **FreeCAD scripts**: AST-based sandbox with blocked imports, blocked calls, blocked dunder attributes. **Well-defended.** Minor gap: `pathlib` is blocked by name but `importlib` is not in the blocked list (though `__import__` is blocked).

### 3.2 SQL Injection — LOW RISK

- `benchmarks/storage.py` uses parameterized queries (verified by comment on line 203). **OK.**
- `db/migrations.py` reads `.sql` files and executes them directly — but these are static migration files, not user input. **OK.**
- `cache/semantic_cache.py` uses SQLite via GPTCache library. **OK.**

### 3.3 Auth Bypass — MEDIUM RISK

- **cluster.py `_p2p_send_handler`** (line 1020-1027): If `cluster_shared_key` is empty, the auth check is skipped entirely (line 1022: `if expected_token:`). Any P2P peer can execute arbitrary LLM requests via the local router without authentication when the key is not set. This is consistent with the overall design (cluster auth is opt-in), but it means a compromised P2P peer gets full router access.
- **provider_admin.py `_persist_env`**: Writes directly to `.env` file based on API input. While env keys are validated against an allowlist earlier in the call chain, the actual `_persist_env` function accepts any dict and writes it. If the allowlist check is bypassed (e.g., new caller), arbitrary env vars can be written.

### 3.4 Secret Exposure in Logs — LOW RISK

- `cluster.py` line 1092: `Authorization: Bearer {settings.cluster_shared_key.strip()}` is set in headers but not logged directly. **OK.**
- No logging of API keys, passwords, or tokens found in the four hotspot files.
- `provider_admin.py`: Log messages reference key prefixes only, not full keys. **OK.**
